# Managed mutation break-glass runbook

Break-glass is not direct human file editing. It is additive evidence for an
exact R4 managed-mutation plan and never replaces normal W04 authority.

## Required evidence

- exact plan, workspace, revision, manifest, operation IDs/kinds/paths, and
  content digests;
- exact GateContext and current workspace observation;
- current W04 R4 dual-human decision and purpose-bound reservation;
- two distinct authenticated humans, neither equal to the requester;
- exact break-glass request binding and short validity window;
- verified snapshot, incident, immutable audit, session, executor identity,
  and mandatory post-validation/reconciliation records.

## Procedure

1. Engage normal planning and review; do not edit the workspace.
2. Verify all evidence through trusted ports immediately before the effect.
3. Persist the durable intent and reservation before the first operation.
4. Recheck exact bytes, containment, links/reparse state, and CAS at actual use.
5. Record every operation and final/partial/uncertain receipt.
6. Reconcile and independently derive the next trusted WorkspaceRevision.

Any missing, expired, revoked, same-principal, requester-self-approved, rebound,
or unverifiable record stops before the effect. The W06 implementation is
fixture-only; this runbook does not enable production break-glass execution.
